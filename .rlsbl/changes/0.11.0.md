## 0.11.0

A fast list on large archives, with a default limit of 50, --limit, --since, and an index-driven --path; a new usage report of the archive's disk use; purge selecting and sizing only what it destroys; and FIFOs, sockets, and devices archived and restored instead of read, under one node_type column in the archive database, whose migration repairs the symlinks and FIFOs older versions recorded as files; and the --json envelope at interface_version 3, with the help document printed by saferm help --json.

<details>
<summary>Context</summary>

On an archive of about 25,000 records, a cold `saferm list` took 36 to 191 seconds because every multi-row query read the database backward, which defeats read-ahead on a copy-on-write, compressing filesystem. Queries now read oldest-first and reverse in memory, `--path` reads only the matching part of the path index, and a bare `list` shows the newest 50 entries with a line saying how many are hidden.

`list --json` now answers with an object, `{"total", "rows"}`, instead of a bare array, so a consumer reads the rows from `rows`. The Go module path is now `github.com/stricttools/saferm`.

Deleting a FIFO used to block until a writer appeared and then record the drained bytes as a file no undelete could restore, deleting a socket failed, and a directory restore silently left out the FIFOs and devices inside the tree. saferm now classifies every path explicitly: special files are kept as `.node` descriptors and recreated on restore, and any other type is refused by name. The database records what each deletion archived in one `node_type` column (schema version 4, a table rebuild that older saferm binaries cannot read), and the migration that adds it repairs the records older versions wrote as files over symlink and FIFO entries, refusing as a whole and changing nothing when it meets a contradiction it cannot repair.

strictcli 0.38.0 moves the `--json` envelope to `interface_version` 3 and replaces `--dump-schema` with `saferm help --json`, so a consumer pinning version 2 must be updated.

</details>

### Breaking

- **The Go module path moved to `github.com/stricttools/saferm`.** The repository lives in the stricttools organization, so `github.com/smm-h/saferm` is no longer this module's path: install with `go install github.com/stricttools/saferm@v0`, and a program importing its packages changes its imports and `require` to the new path.
- `saferm list` shows the newest 50 entries by default and ends with a line saying how many are hidden and how to see them; `--limit N` changes the count and `--limit 0` shows every entry. The `--json` payload of `list` is now an object, `{"total": N, "rows": [...]}`, instead of a bare array of rows: a consumer reads the rows from `rows`, and `total` says how many the selection matched before the limit. `capabilities` names the new `list-limit` feature.
- **The archive database records what each deletion archived in one `node_type` column.** Opening the database with this saferm rebuilds its table (schema version 4), replacing `is_directory` and the symlink inference with `node_type`; a saferm older than this release can no longer read or write a database this one has opened, so every saferm on the machine must be upgraded together.
- **The `--json` envelope is `interface_version` 3**, from strictcli 0.38.0: it gains an `output` member, which saferm leaves `null` because every line it prints is carried in `diagnostics`, and the help document with every payload schema is printed by `saferm help --json`, which replaces `saferm --dump-schema`. A consumer pinning `interface_version` 2 must be updated.
- **`saferm list` marks directories and symlinks with their node type words, `[directory]` and `[symlink]`, instead of `[dir]` and `[sym]`.** Every marker in the table is now the word `info` prints as the Type and the `--json` payloads carry as `node_type`; a script matching `[dir]` or `[sym]` in the table must match the new words.
- **The Homebrew formula moves to the stricttools tap: install with `brew install stricttools/tap/saferm`.** New releases are no longer published to `smm-h/tap`; a machine that installed from it switches taps to keep receiving updates.
- The `saferemove` npm package declares the Node versions it supports, `>=22`; npm warns when installing it on an older Node.

### Features

- saferm list is fast on a large archive again: every multi-row query now reads the database oldest-first and reverses in memory, instead of walking it backward, which on a copy-on-write, compressing filesystem took minutes for a cold list of about 25,000 records. The order shown is unchanged (newest first), and records deleted in the same second now reliably list highest id first.
- `saferm list --path` reads only the part of the archive's path index the pattern's literal prefix can match, then fetches just the matching records, instead of reading every record and filtering them one by one. A malformed pattern is now refused with exit 2 whatever the archive holds; before, it was refused only when some archived path reached the malformed part of the pattern.
- New `saferm usage` command: reports what the archive occupies on disk (the archive directory, the part still linked from outside it, the part no record names, and the database), then breaks the records still in the archive down by age and by original directory, each row giving the record count, the size captured at delete time, and the space the entries take now. `--directory-depth` (default 3) sets how many leading directory components name a group and `--directory-limit` (default 20, 0 for all) how many groups are listed; `--json` carries every figure in bytes.
- New `saferm list --since <duration>`: lists only the entries deleted within the duration, in the syntax `purge --older-than` takes (`24h`, `7d`, `2w`, `1m`), and combines with `--path` and `--limit`. `capabilities` names the new `list-since` feature.
- The documentation describes `list`'s default limit of 50 with `--limit` and `--since`, its `{"total", "rows"}` JSON payload, the new `usage` report and its payload, and how `purge --all` and `--larger-than` select and size what they destroy.
- The documentation describes the node types and their `node_type` column, how FIFOs, sockets, and devices are archived as `.node` descriptors and recreated, the `entry-corrupt` status, the migration that repairs the records older versions wrote as files, and the `node-type-<type>` capability features.

### Fixes

- **The tool describes itself with one sentence everywhere, including `--help`.** The `--help` header, README, docs site, npm and PyPI metadata and the Homebrew formula now carry the same line.
- `saferm purge --all` and `--larger-than` no longer select records that were already restored or purged: the dry run's item count and size now cover only what the purge destroys, and a restored record is no longer marked purged by a later `purge --all`.
- `saferm purge --dry-run` now says how much disk the purge frees as what the selected archive entries occupy, instead of summing the sizes the records captured at delete time: a compressed directory counts as its .tar.zst, and a file still linked from outside the archive counts as nothing, with a note saying how many such entries were selected.
- A path swapped for a FIFO, socket, device, or symlink while `saferm delete` reads it now fails that path's deletion instead of blocking forever on the FIFO or hashing whatever the symlink names.
- **`saferm delete` archives FIFOs, sockets, and devices instead of reading them.** Each is kept as a `<uuid>.node` descriptor of its node type, mode, and device numbers, and `undelete` recreates it (a socket on Linux only; a device needs the privilege `mknod` asks for, and without it the restore fails and the record stays restorable). Before, deleting a FIFO blocked until a writer appeared and then recorded the drained bytes as a file no undelete could restore, and deleting a socket failed. Any other type of file is refused with an error naming it. `list` marks the new node types `[fifo]`, `[socket]`, `[character-device]`, and `[block-device]`, the `node_type` member of the `list`, `info`, and `undelete` payloads gains `fifo`, `socket`, `character-device`, and `block-device`, and `capabilities` names one `node-type-<type>` feature for every node type.
- **A directory restore brings back the FIFOs, sockets, and devices inside it.** Before, `undelete` printed "Restored" and exited 0 while silently leaving out every FIFO and device in the tree, and deleting a tree that held a socket failed. A member type the restore cannot recreate now fails the restore and takes back what it wrote, and a delete refuses to remove a tree whose member changed type after it was archived, which used to destroy that member unarchived.
- `saferm info` reports an archived copy that is not what its record says it is, such as a special file's descriptor of another node type, as `entry-corrupt` (a new value of the payload's `status`) with the reason, instead of `restorable` while `undelete` refused it.
- **Opening an archive database written by an older saferm repairs the symlinks and FIFOs it recorded as files.** The migration to schema version 4 reads every record's archived copy, writes each such copy in its node type's form (a `.symlink` target file, or a `.node` descriptor), and gives the record that node type, so `info` reports it restorable and `undelete` brings it back as what it was. Any other contradiction stops the migration before anything changes, with an error naming the records.
- The machine-surface page names the committed help document where it now is, `.strictmetadata/.cli-schema/schema.json`.
- The PyPI package `saferm` builds with hatchling, carries a real copy of the README (generated with the root one) instead of a symlink that pointed outside the package, and its source package leaves out the repository's private paths and stale build metadata.
